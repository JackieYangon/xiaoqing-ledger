# Xiaoqing Ledger v1.0.4 — Local setup and sign-in recovery

This release fixes the local configuration and build-directory problems that could prevent the mini program from opening or signing in. A project imported from the repository root now points to the output produced by its selected build command, and release preparation checks that the required account configuration is present.

**Release status: Preview source release.** This keeps the existing preview status while publishing the source and setup fixes.

## Changes

- `dev:mp-weixin` selects `dist/dev/mp-weixin/`; `build:mp-weixin` selects `dist/build/mp-weixin/`. This resolves the missing `app.json` error caused by an absent or mismatched `miniprogramRoot`.
- Ordinary setup, type checks and other configuration-generation steps preserve the selected development or production directory.
- Setup retains an AppID already present in the local project when no replacement is supplied. Precedence is the local process environment, `.env.local`, then the existing AppID. An explicitly empty AppID selects guest mode.
- Configuration inputs are parsed and validated before generated files are written. Invalid arguments, identifiers and malformed configuration files leave the existing configuration intact; repeated setup avoids unnecessary writes.
- Upload preparation, including `--prepare-only`, requires both an AppID and a cloud environment. This prevents preparing a release with missing account settings while keeping ordinary guest-preview builds available.
- The README now documents missing-environment sign-in errors and stale compilation-cache recovery. Repository documentation, commit messages and release notes are maintained in English; the application interface remains unchanged.

## Updating and recovering sign-in

Keep your own `XQ_APP_ID` and `XQ_CLOUD_ENV` in the local, untracked `.env.local` file or local process environment. Do not commit actual deployment values or put an AppSecret in frontend configuration. The cloud environment must contain your deployed `ledger` function.

From the repository root:

```powershell
pnpm install --frozen-lockfile
pnpm build:mp-weixin
```

Wait for the build to finish, then reopen the repository root in the developer tools and compile. Confirm that `project.config.json` points to `dist/build/mp-weixin/` and that the directory contains `app.json`. For active development, use `pnpm dev:mp-weixin` and leave that compiler running instead.

If the earlier missing-environment error remains after rebuilding with the correct local values, clear **only the compilation cache**, then recompile and sign in again. Preserve application storage and user data: clearing all data can discard legacy records, pending requests and remembered sessions. Generating configuration alone does not replace an already compiled or cached bundle.

Before preparing an upload, configuration can be checked explicitly with:

```powershell
node scripts/prepare-local-config.cjs --mp-mode build --require-cloud
```

## Verification and scope

Checks completed on 2026-11-02:

- All 11 `pnpm test` entry points passed. Cloud and upload services in these tests are mocked.
- `pnpm type-check` passed.
- The production mini program build passed all package checks: main package **300966 bytes**, `requiredComponents` injection, and **9** media assets with a largest size of **51787 bytes**.
- Generated output was checked against application version **1.0.4**, manifest version code **10004**, the root target `dist/build/mp-weixin/`, **14** pages and a populated cloud environment. Actual deployment identifiers remain local.

Sign-in was verified in the developer tools simulator after rebuilding and clearing only the compilation cache. The personal account was visible, with a synchronized cloud status and a recent synchronization timestamp; the tested ledger contained zero entries. This was not a physical-device test.

Regression coverage includes build-directory switching, AppID preservation and precedence, explicit guest configuration, required cloud settings for upload preparation, invalid-input write protection and repeated configuration generation. Existing ledger records, budgets and backup formats remain unchanged; no data migration is required.

This release does not change backend authentication logic. The verified recovery concerns local configuration and compiled code. Full device, multi-account and desktop acceptance remain separate checks.
